# AGENTS.md

How to work in this repository, for coding agents and human contributors
alike. The [README](README.md) covers what the project is; this file covers
the rules of the road.

## Commands

```
pnpm install      # Node 22+, pnpm 10
pnpm typecheck    # tsc --noEmit over pipeline/
pnpm test         # vitest
```

Milestone 1 adds `pnpm validate` (schema + vocabulary + referential checks);
milestones 2–4 add the Pleiades join, claim derivation, and exports. Until a
script exists in `package.json`, it doesn't exist.

## Invariants

These are enforced by schema and CI, not left as conventions. Do not work
around them.

1. **No point dates.** Every date is a `not_before`/`not_after` range with an
   explicit `dating_basis`. A single-year attestation is a range of width one.
2. **No coordinates in this repository.** Places are Pleiades URIs with a
   `place_certainty` grade. Coordinates are joined from the Pleiades dump at
   build time.
3. **Every claim traces to a citable source.** An evidence item without a
   source citation block is invalid.
4. **`data/claims/` is derived.** It is regenerated by the pipeline from
   `data/evidence/`; CI fails if committed claims drift from the derivation
   rules. Never hand-edit anything under it.
5. **Human verification before commit.** LLM-assisted extraction of evidence
   from sources is welcome; committing it unverified is not. Every evidence
   item is checked against the source by a person before it lands.

## Commits and pull requests

- Atomic conventional commits: one logical change per commit,
  `type(scope): summary` (`feat`, `fix`, `docs`, `build`, `ci`, `chore`,
  `data`).
- Commit bodies and PR descriptions explain **why, not what**. The diff
  already shows what changed; record the reasoning, the alternative you
  rejected, or the source you followed.
- Keep them concise. A one-line body that carries the reason beats three
  paragraphs of restated diff.
- **One concern per PR, and small.** A schema change, one script, one batch
  of evidence items. If the description needs more than two short paragraphs,
  or the diff mixes schema, pipeline, and docs, split it.
- A PR description states the why and the decisions the reviewer should
  weigh. It is not a list of changed files.
- No meta commentary about the PR itself. Describe the change and its
  evidence, not the mechanics of producing it: rebases, force-pushes, how
  the diff was scoped, merge order, or CI runs. If the base branch or merge
  order matters to a reviewer, put it in a PR comment, not the description.
- Plain prose in commit bodies, PR descriptions, and docs: short
  declaratives, a checkable fact per sentence, no em-dashes.
- All work goes through a PR. CI must be green to merge.
- PRs that add or edit files under `data/` use the data template:
  [.github/PULL_REQUEST_TEMPLATE/data.md](.github/PULL_REQUEST_TEMPLATE/data.md).

## Boundaries

- Never commit `sources-raw/` or cache directories (`.pleiades-cache/`,
  `.cache/`). They hold downloaded scans and dumps, not project data, and are
  gitignored.
- `data/` is published under CC BY 4.0. Only add material whose license
  permits that, and cite where it came from.
- The research notes this project was designed from are private and live
  outside the repository. Public docs are written fresh in `docs/`; do not
  import files from outside the repo tree.
